# THE BLACKCHAIN – Knowledge Base

> **Назначение репозитория** — хранить *нормы работы сценарной комнаты* и сопутствующие справочники **раздельно**, чтобы протокол оставался лёгким, а вспомогательные материалы росли «по спросу».

---

## 1. Дерево каталогов

```
docs/
├── CORE_PROTOCOL.md          # Неизменяемый «закон комнаты»
├── PROFILE_LIBRARY/          # Плагины-персоны (по одному YAML/MD на участника)
├── PASS_GUIDES/              # Шаблоны конкретных процессов (арка, beat-sheet …)
├── ROOM_LOGS/                # Исторические логи спринтов (§ Фиксация)
└── legacy/                   # Архив прежних версий (v5.0 и старше)
```

*Первые четыре раздела — **живые**; `legacy/` — read-only.*

---

## 2. CORE_PROTOCOL.md — принципиальные правила

* 5 модальностей: **ШТОРМИНГ / АНАЛИЗ / АТАКА / РЕШЕНИЕ / КАМЕРТОН**  
* Команды управления: **ФИКСАЦИЯ**, **СВЕРКА ЧАСОВ**  
* **Шоураннер** — единственный, кто утверждает или меняет CORE; обсуждать может кто угодно  
* Всё остальное вынесено в отдельные файлы, чтобы протокол был < 4 страниц

---

## 3. Быстрый старт работы

| Шаг | Действие | Где писать |
|-----|----------|-----------|
| 1   | Создайте файл лога: `ROOM_LOGS/YYYY-MM-DD_<тема>.md` | `ROOM_LOGS/` |
| 2   | В начале лога объявите **Состав спринта**:<br>`Методология: Tony Gilroy, Robert McKee` | в том же лог-файле |
| 3   | Ведите беседу, соблюдая модальности и фиксируя ключевые решения блоками `ФИКСАЦИЯ` | ― |
| 4   | При необходимости откройте нужный шаблон из `PASS_GUIDES/` и вставьте в лог ссылкой | ― |
| 5   | Если обнаружили новый приём эксперта — добавьте **одну строку** в его файл в `PROFILE_LIBRARY/` | `PROFILE_LIBRARY/<Name>.yaml` |

---

## 4. Как расширять содержимое

### 4.1. Профили персон (`PROFILE_LIBRARY/`)
* **Минимальные поля**: `name`, `philosophy`, `signature_moves[]`, `blind_spots[]`.
* Всё остальное — опционально; добавляйте по мере реальной выгоды.
* Версионируйте внутри файла комментом: `# v1.2 – добавлено …`.

### 4.2. Pass Guides (`PASS_GUIDES/`)
* Один файл — один процесс (пример: `Character_Arc_Pass.md`).
* Формат свободный, но должен содержать: цель, шаги, пример команды.

### 4.3. Room Logs (`ROOM_LOGS/`)
* Именуйте `YYYY-MM-DD_<коротко>`.
* Каждая сессия — отдельный файл.  
* В конце дня убедитесь, что все `ФИКСАЦИИ` сохранены.

### 4.4. Обновление CORE_PROTOCOL
* Правит только **Шоураннер**.  
* После изменения добавить в конец лога строку:  
  `ФИКСАЦИЯ: CORE_PROTOCOL vX.Y утверждён`.

## 5. ЧАВО

| Вопрос | Ответ |
|--------|-------|
| **Нужно ли тегировать профили?** | Нет. Теги, роли-шляпы и т.п. добавляются, *если* реально экономят время. |
| **Можно ли удалять старые Pass Guides?** | Только после согласования с Шоураннером; лучше переместить в `legacy/`. |
| **Что делать, если два лога в один день?** | Добавьте суффикс: `2025-07-13_a.md`, `2025-07-13_b.md`. |

---

## 6. Контакты и участие

* **Шоураннер** — финальный арбитр по структуре репозитория.  
* Любые pull-requests / предложения начинайте с обсуждения в текущем лог-файле, чтобы попасть в историю проекта.
