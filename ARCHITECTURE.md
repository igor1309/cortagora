# Repository Architecture

Этот документ фиксирует правила организации репозитория cortagora.

## 1. Layers

Репозиторий содержит несколько слоёв, каждый со своей семантикой:

- **works/** — конкретные проекты/произведения (единица ответственности)
- **world/** — глобальный world-material (общий банк мира; не канон)
- **framework** — набор рабочих рамок и инструментов мышления:
  - domains/, protocols/, modalities/, personas/, writing/
- **tools/** — утилиты и эксперименты
- **_inbox/** — входящее (до сортировки)
- **logs/** — журналирование

## 2. Work and scope

Scope начинается там, где присутствует `Work.md`.

Scope может быть:
- проектным (`works/<work>/Work.md`)
- сезонным (`works/<work>/s01/Work.md`)
- любым вложенным уровнем при необходимости

Каждый scope может иметь собственные (опциональные) папки:
- `world/` — world-material этого scope
- `research/` — reference-материалы этого scope
- `sandbox/` — идеи/наброски/альтернативы этого scope
- `story/` — сцены, синопсисы, версии текста

## 3. Presence-based

Наличие папки означает наличие данных на уровне scope.
Отсутствие папки означает отсутствие данных на этом уровне.

Никаких обязательных “пустых” папок.

## 4. Nearest wins

Контекст собирается снизу вверх:
1) текущий scope
2) родительский scope
3) корневой уровень репозитория

При конфликте побеждает ближайший (nearest wins).

Пример:
`works/deceptor/s01/world/` переопределяет `works/deceptor/world/`,
который переопределяет корневой `world/`.

## 5. World vs canon

`world/` — это **world-material**: описание мира, атмосферы, институциональной логики, гипотез.
Это не обязательно консистентный “канон”.

**Canon** (если нужен) фиксируется явно внутри work (например в `works/<work>/canon/`),
но наличие `canon/` не является обязательным стандартом репозитория.

Правило: ничего из `research/` или `sandbox/` не становится каноном автоматически.

## 6. Framework folders

- `domains/` — предметные области, методики и базовые рамки (reference + мыслительные схемы)
- `protocols/` — протоколы взаимодействия и рабочие стандарты
- `modalities/` — режимы работы/мышления
- `personas/` — персональные профили и стили
- `writing/` — методички по нарративу

Эти папки надпроектные и могут использоваться любым work.

## 7. Git policy

Git используется как:
- хранилище
- история изменений

Точка истины: `trunk`.
Сабмодули и сабтри не требуются.
Миграции выполняются малыми шагами, чтобы не ломать навигацию.
